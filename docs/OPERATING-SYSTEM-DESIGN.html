Anabtawi Operating System

A company of AI departments that runs the Anabtawi brand with Rami as the board. Departments are folders of text. Runs are scheduled Claude Code sessions on the Max plan. GitHub is the record and the approval button. Money moves only through a hands workflow no model can read.

2026-09-05supersedes DECISION-CONTROL-PLANE.mdfull text: docs/OPERATING-SYSTEM-DESIGN.md

The verdict in one page

  • A department is a folder of text. Charter, skills, memory, tools file. The pilot proved it: two departments produced daily, cited, correct findings and changed behaviour from inbox files without a prompt edit.
  • The unit of work is a run, not an agent. One fresh Claude Code session, one charter, one repo, then it ends. State lives in files. The persistent chat bot is what stalled in the pilot; the bounded run is what worked.
  • The scheduler is Claude Code Routines verified: Pro and Max plans, cron with a one-hour minimum, fresh cloud session per fire, connectors and a committed .mcp.json, pushes to claude/ branches, drawn from the subscription plus a daily run cap. No server. Exit is a launchd plist per department on the Mac mini.
  • Approval is a pull request merge. A proposal is a PR that moves a file from approvals/pending/ to approved/. Rami reads the body on his phone and taps Merge. Push notification, second confirm, expiry, audit trail, family visibility: zero code.
  • Money moves only through the hands workflow. A GitHub Actions job on that merge runs a deterministic script, fetches the SP-API token from 1Password at run time, executes exactly the approved payload with the Agent/ header, appends the ledger. No model in the loop. Amazon Section 19 is met by construction.
  • The goal layer is text (strategy/STRATEGY.md, GOALS.md, a decision journal, a prediction log) owned by the Chief of Staff's weekly run, which scores every key result and writes the ranked decisions for Rami. The separate CEO agent is folded in as separate runs.
  • Learning compounds through files, not a memory product: dated observations, pruned memory, playbooks with provenance and 90-day decay, a prediction log scored monthly, a decision journal, and a monthly attempt to falsify each playbook.
  • Paperclip is dropped, Grok Bot retired, Codex optional as an independent second opinion on money proposals from the Mac mini.
  • The Mac mini is hands and fallback, not the heartbeat. If it is off, the company still runs.
  • A second brand is one afternoon: new repo from the template, new DataDoe organisation, new Routines. The OS ships as a Claude Code plugin.

Monthly cost outside launch sprints: about USD 300 to 400 on top of the subscriptions already paid. Details in the cost section.

What the evidence says

The pilot, verified from the repo

Two departments on a shared cloud computer at T0 with one read-only key ran three days and produced a 29-row daily cover table with velocity, cover, lost revenue (CAD 1,241 to 1,286 a day), inbound ETAs, expiry flags and five cited export ids; and an account-health file that classed three suppressed parent listings correctly as a catalog attribute fix rather than an appeal, sent a compliance hold, and found that DataDoe's real-time notification sources were disabled. Both refused to guess. An urgent request superseded an hour later by a normal one was handled correctly and honoured in every later run.

Failures had structural causes: a shared clone with relative paths (fixed in the run procedure); three near-duplicate requests to a department that did not exist (fixed by "one open request per type per SKU set"); the Chief of Staff stalled on its multi-step bootstrap, never posted a brief, and left Rami's second request unanswered past its deadline; every commit carried one shared identity. The lesson is not that coordination fails. A persistent chat bot executing a checklist across days is the wrong unit of work; a scheduled, bounded run with a fixed procedure and a state file is the right one.

The unit of work is a run

One Routine fire, one fresh session, one prompt naming the department and the run, one clone of main, work through the department's tools, one push to claude/<dept>/<date>, one pull request, then the session ends. A persistent identity with a chat surface is what stalled in the pilot and what Vending-Bench shows melting down over long horizons. Skills alone are procedures without a caller; workflows-as-code need a programmer for every change, and the pilot showed that the changes that matter are plain-text corrections. The run is the composition: a charter calls skills on a schedule, with the deterministic parts pushed into scripts and hooks.

Run procedure, version 2

  1. Start from a clean clone of main. No department clones, no rebase.
  2. Read the constitution, the charter, MEMORY.md, strategy/GOALS.md, the inbox, the state files the charter names, and state/calendar.md.
  3. Answer inbox items first. An assignment wake means answer and stop.
  4. Do the charter's work. Writes go through the Ads MCP under the hook (T1) or an approval file (T2 and above).
  5. Write state/<name>.md with today's date, a served_objectives list, and a predictions block for any proposal.
  6. Write memory/<date>.md; update MEMORY.md only for durable facts.
  7. Commit as the department, push to the claude/ branch, open one PR. State-only PRs auto-merge; PRs with approval files or playbook changes wait.

Coordination

Three channels in rising cost. Shared state in state/*.md is read before proposing; the Office rejects proposals that ignore it. Typed requests keep the existing schema with two rules from the pilot promoted: one open request per type per SKU set, updated not duplicated; and a request to a department that has not run in seven days is answered by the Office on its behalf and flagged. Meetings are one Office run spawning one subagent per department to state a position from its files, resolved against the constitution, written to meetings/. The coordinator will not stall this time because it never executes multi-step work across days: bootstrap is Rami's, and each Office run is one bounded procedure with a hard stop.

Strategy and the goal loop

strategy/STRATEGY.md
Mission, north star and its computation, quarterly posture, department mandates and boundaries, non-negotiables, this quarter's one or two wildly important goals, deferred items with triggers, revision log.
strategy/GOALS.md
YAML: quarter, north star target and baseline, one to three objectives with key results (metric, target, baseline, current, as-of), owner, definition of done, status; anti-thrash lock and override triggers; append-only weekly scorecard.
strategy/decisions.md
The decision journal: one entry per T2 or T3 decision and per plan change, with evidence pointer, predicted outcome, review date.
ledger/predictions.jsonl
One line per proposal: metric, predicted value, horizon, source. Scored monthly; the calibration per department and action class feeds the ratchet.

North star for the first quarter: contribution margin after ads, CAD-normalised, CA plus US, monthly. The constitution's targets become key results: CA CAD 20k a month by March 2027 with ten activated SKUs; hero stockout days zero; US stock live 2027-01-15.

The Office's three runs

Daily brief, 07:00. Any state file not dated today leads the brief as a failed department. Expires stale approvals and closes their PRs. Lists requests past needed-by with both positions. Pulls yesterday's numbers by marketplace against the seven-day average. Writes briefs/<date>.md under 400 words, every number cited, posts it to Slack and emails the family, and opens GitHub Issues labelled for-rami for tasks that are his, each with evidence, impact and deadline. Hard cap of five decisions; if none, one line says so.

Weekly review, Monday. Scores each key result with an isolated subagent per result, flags only two-consecutive-week breaches, appends the scorecard row, writes the ranked decisions list, chairs the Monday meeting, and proposes tier promotions as a one-line charter PR when the ratchet's numbers are met.

Monthly review, first business day. Chairs S&OP; falsifies playbooks against thirty days of outcomes; scores the prediction log; proposes scoped repairs to milestones as a diff; writes the posture paragraph as a PR; prunes memory; runs the Agent Policy self-audit over the ledger.

Anti-thrash: quarterly objectives are locked until the date in GOALS.md, changeable at the boundary or by a named override trigger; monthly milestones change only by a scoped repair; weekly tasks regenerate freely; a single week's breach changes nothing; every plan change has an evidence pointer; the Office proposes quarterly changes as PRs and never merges one.

Knowledge and learning

Nothing lives in Claude Code's auto memory: cloud sessions are fresh machines, so any memory not in the repo does not exist. That discipline is what makes the second brand cheap.

The loop. Daily observations with sources accumulate. The Monday review classifies the week's observations as new, reinforcing or contradicting a playbook fact and writes the diffs. A fact not reinforced in 90 days is marked decaying and moved out of the active section; a decayed fact cited in a proposal must be re-verified first. The monthly review tries to falsify each active fact against the last thirty days of outcomes and records the verdict. The brief's "Learned" section shows what was promoted or demoted, so Rami watches the company's beliefs change.

Measurably better. Every proposal states what it expects to happen and by when. The Office scores each prediction at its horizon and keeps a calibration per department and action class. That answers "is the system learning" with a number, and it becomes a ratchet condition: an action class earns T1 by predictions that came true, not only by approvals.

Retrieval and evals. Grep over markdown and DuckDB over the ledgers until the repo reaches thousands of files. An evals/ folder of twenty to thirty golden cases, past state files with the decision Rami actually made, is replayed quarterly and whenever a charter or skill changes.

The approval and money path, end to end

T2 proposal, step by step.
  1. A run writes approvals/pending/<id>.md with the existing schema plus prediction fields and a payload in the exact shape the hands script executes.
  2. It pushes and opens a PR titled with the one-line proposal. The body is the proposal, evidence, impact, and what happens if rejected. Labels: approval, t2, money, department.
  3. GitHub notifies Rami's phone. He reads the body, taps Approve, then Merge. For money PRs a branch rule requires the approving review, so it is two deliberate taps.
  4. The merge moves the file to approved/; a small Actions step fills decided_by and decided_at from the merger's identity, so no model can forge them.
  5. The hands workflow runs on push to main touching approvals/approved/: validates the front matter and payload per action type, checks expiry and the Amazon floor, fetches the SP-API token from 1Password with a service-account token held as a GitHub secret, executes with User-Agent: Agent/AnabtawiOS, writes request and response to ledger/actions.jsonl, moves the file to executed/ or failed/, commits as anabtawi/hands, posts one line to Slack.
  6. Rejection is closing the PR; expiry is the Office closing PRs older than 48 hours. Expired proposals are re-proposed with fresh data, never executed stale.

State changes that do not need Rami

Option A, recommended: path-scoped auto-merge. A 30-line Actions check passes only when a PR from a claude/ branch touches nothing outside state/, memory, requests/, briefs/, meetings/, and kpis.csv. Option B: direct push to main for those paths, which needs the history rewrite and is enforced by procedure only.

T1 under a hook

Advertising calls the official Ads MCP directly. A PreToolUse hook in the committed .claude/settings.json runs scripts/guard_ads.py on every Ads write: plus or minus 15 percent on bids, plus 25 percent on budgets, the daily cap across campaigns, one change per target per 24 hours from the ledger, and the blackout and stockout-risk lists in state/. A breach blocks the call with the reason. A PostToolUse hook appends every successful write to the ledger. Guardrails live in code, which is what Project Vend 2 and the long-horizon guardrail literature both ask for.

What never goes to a model

SP-API refresh token and client secret, the Ads credential used by hands, the 1Password service-account token, GitHub credentials (the cloud GitHub proxy keeps them outside the VM). Read-only keys for DataDoe and Keepa are cloud-environment API credentials attached by Anthropic's proxy. Whether that feature can attach DataDoe's custom header is unknown test week 1; the fallback is an environment variable holding a read-only key that is revoked in one click.

Five daily runs plus the brief; about twelve on a Monday. The daily run cap's number is unknown read week 1. If it binds, one morning Routine spawns the daily departments as subagents in calendar order and then the brief: one run, fresh context per department.

Events. DataDoe scheduled agents watch Buy Box loss, cover under floor, suppressed listings, one-star reviews, spend over twice baseline, account status, and post to Slack. If DataDoe can call a webhook test week 2, it fires the event Routine with the alert as text, which arrives labelled untrusted. Otherwise the next scheduled run reads Slack.

Capacity. Routines draw down subscription usage like interactive sessions. At the planning number of 150k to 500k tokens per run, five daily runs are one to two and a half million tokens a day; Max 20x is expected to carry the calendar plus Rami's sessions. Week one measures real usage before adding departments. The "ordinary individual usage" clause is the one policy risk; Routines are Anthropic's own feature for unattended runs on these plans, and one email to Anthropic describing the use is a week-one task.

Fallback. runtimes/launchd/ holds one plist per Routine running the same claude -p command in a fresh clone with secrets injected by op run. Switching is pausing the Routines and loading the plists. Dead-man's switch. An Actions cron at 07:30 checks that the brief and every daily state file are dated today and alerts otherwise; independent of Anthropic, DataDoe and the Mac mini. Codex. Optional nightly codex exec on the Mac mini that writes an independent review comment on each money PR. Graduation. Managed Agents run the same folders if the plan's limits ever bind for good.

The second brand

The operating system becomes a Claude Code plugin in its own repository: skills (run procedure, export, cover, PO proposal, negatives, listing standard, brief, review, falsification), hooks, scripts, templates (constitution, charters, GOALS.md, dossiers, workflows), and the department subagents used in meetings. Brand repos install it by version and hold only what is theirs: the constitution's numbers, tier lines, dossiers, state, memory, ledger, strategy. Instantiating a brand is a repo from the template, a DataDoe organisation, the SP-API app and Ads credential in 1Password, the Routines from the calendar, a Slack channel and an email list. One afternoon, then a T0 week. Playbooks are brand-specific by default; a fact promoted to the shared plugin needs two brands' evidence.

Then: keep the constitution, charters, skills, state, requests, approvals, ledger, dossiers, playbooks and conventions; add strategy/, the workflows, the hooks settings, the four scripts, evals/, runtimes/routines/ and runtimes/launchd/, and a runbook; edit the constitution's run procedure and channels, the merged charter, the conventions for prediction and goal fields; retire the Grok Bot and Paperclip runtimes to an archive folder; fix the pilot's leftovers: seed products/ and mark the heroes, fill the supplier file (every cover number today assumes lead time zero), replace the 09-03 calendar line, answer the open request, clear the duplicate stockout-risk requests, decide the history rewrite.   • Routines change or vanish: launchd on the Mac mini, or Actions cron with the subscription token. Tripwire: two missed daily runs in a week not explained by usage.
  • Usage cap binds: bundle departments into one morning Routine; then usage credits; then Managed Agents. Tripwire: the brief is late twice.
  • Anthropic enforces the individual-usage clause: same ladder; a funded API key keeps the calendar running at metered cost.
  • DataDoe lag or outage: Nova trial as cross-check; the private app can read.
